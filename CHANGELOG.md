# Changelog

Все заметные изменения продукта. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
номера версий — [семантическое версионирование](https://semver.org/lang/ru/).

## [Не выпущено]

Этап 1: каркас продукта, локальный стек и конвейер проверок. Этап 2 в работе:
сенсор встаёт на пути трафика и получает первые приманки.

### Добавлено
- Сенсор (Go): проверка конфигурации с отказом стартовать при неверной,
  служебный слушатель с `/healthz` и `/readyz` только на localhost,
  таймауты против медленных клиентов, корректная остановка, самопроверка
  `sensor healthcheck`.
- Control plane (Python, FastAPI): то же устройство и те же правила;
  документация API и журнал доступа выключены, заголовок `server` не отдаётся.
- Образы: сенсор на distroless (около 4 МБ, без shell), control plane без pip;
  все процессы не от root, базовые образы по digest.
- Локальный стек одной командой `make dev`: сенсор, control plane, PostgreSQL,
  NATS; Juice Shop в профиле demo. Изолированная сеть без выхода в интернет,
  секреты файлами, порты только на 127.0.0.1.
- CI: линтеры, типы, тесты с порогами покрытия, сборка образов и запуск стека.
- Проверки безопасности: gitleaks, govulncheck, pip-audit, 8 собственных правил
  Semgrep, CodeQL, hadolint, Trivy; Dependabot с выдержкой 7 дней.
- Git-хуки и проверка формата сообщений коммитов; правила защиты ветки `main`.
- Документация: модель угроз, 17 ADR, инструкция по продукту, чек-лист этапов,
  глоссарий.
- Решения этапа 2: политика обнаружения описывается данными и будет
  редактироваться в веб-интерфейсе вместе с собственными правилами
  администратора (ADR-0018); вторая учебная цель — VulnBank, в изолированной
  сети (ADR-0019). Модель угроз 1.6: угрозы T15 и T16.
- Учебные материалы `docs/learning/`: как читать Go-код продукта с чек-листом
  ревью, шаблон и первый разбор шага.

- Сенсор проксирует трафик в защищаемое приложение (ADR-0021): прозрачно
  для приложения и пользователей, с таймаутами на каждом этапе, пределом
  одновременных соединений (`SENSOR_MAX_CONNS`) и нейтральными ответами
  на сбой приложения. Адрес приложения — обязательная переменная
  `SENSOR_UPSTREAM_URL`.
- `make dev-demo` поднимает Juice Shop за сенсором на 127.0.0.1:8080;
  `make smoke` проверяет, что запрос через сенсор доходит до приложения.
- `make dev-vulnbank` поднимает вторую учебную цель — VulnBank — за своим
  экземпляром сенсора на 127.0.0.1:8081 (ADR-0019). `make smoke` и CI
  проверяют путь запроса через сенсор для обеих учебных целей.
- Сенсор определяет адрес клиента за балансировщиком или CDN (ADR-0022):
  доверенные прокси задаются в `SENSOR_TRUSTED_PROXIES`, адрес клиента —
  самый правый недоверенный адрес в `X-Forwarded-For`. По умолчанию
  не доверяет никому.
- Сенсор записывает события (ADR-0023): запуск, остановку и попытки
  `CONNECT` — в файл JSON Lines (`SENSOR_EVENTS_FILE`) через буфер, который
  никогда не задерживает запрос. Счётчики — на `/metrics` служебного
  слушателя: потерянные события, отказы приложения, насыщение соединений.
  `make dev-events` показывает события демо-стенда.
- Сенсор работает в режиме fail-open (ADR-0024): сбой или перегрузка
  обнаружения не ломают сайт. Паника пропускает запрос в приложение
  и записывается событием; при перегрузке проверяется каждый 10-й запрос
  до восстановления. Каждый переход — событие critical, строка ERROR
  и метрика `sensor_fail_open`.
- Первые ловушки (ADR-0025): политика обнаружения — JSON-файл
  (`SENSOR_POLICY_FILE`) со строгой проверкой. Ловушка — точный путь,
  режим `enforce` отвечает фейковым файлом, `observe` только записывает
  касание. Касание — событие `decoy.touch`. Политика перечитывается
  по `SIGHUP` (`make policy-reload`); при ошибке сенсор остаётся
  на прежней политике, при запуске — на последней валидной копии.
  Демо-стенд ставит учебные ловушки `/.env`, `/.git/config`, `/backup.sql`.
- Ловушки, которые нельзя вызвать с чужого сайта (ADR-0026): условия
  `methods` и `preflight_only` у ловушки на пути и cookie-ловушка
  (`cookie_traps`) — сенсор выдаёт cookie со «служебным» значением,
  и запрос с изменённым значением записывается касанием. В событиях —
  заголовки `Sec-Fetch-*`. Новые метрики: `sensor_cookie_touches_total`,
  `sensor_cookie_baits_total`, `sensor_preflights_refused_total`.
  В демо-стенде — учебные приманки №8 («внутренний» метод API) и №9 (cookie).

### Безопасность
- Правило Semgrep go-no-sensitive-http-logging уточнено: ловит утечки через
  `slog.StringValue`, `slog.AnyValue`, `slog.GroupValue` и `With`, которые
  раньше пропускало, и больше не срабатывает на любой вызов `.String()`
  у тела запроса (например, сравнение ответа в тестах).
- Сенсор не может стать открытым прокси: адрес приложения только из
  конфигурации, `CONNECT` отвергается, прокси из окружения не используется
  (угроза T17). Заголовки, которыми клиент выдал бы себя за другой IP,
  до приложения не доходят (T1). Запрос приложению собирается заново,
  противоречивые запросы отвергаются (T18).
- Juice Shop переведён в изолированную сеть без выхода в интернет и без
  порта на хосте: доступ только через сенсор (T16).
- VulnBank собирается своим образом вместо штатного запуска автора (там база
  открыта в сеть, доступ к Docker и root): исходники по SHA коммита, зависимости
  с хешами, не root, своя изолированная сеть и база. Проверка контейнеров:
  `ADD` по сети разрешён только из git по полному SHA коммита (D5), то же
  для исходников из git в compose (новое правило C8).
- Control plane переведён на distroless и Python 3.13 (ADR-0020): в образе
  больше нет shell, apt, perl; уязвимостей HIGH без исправлений 44 → 22,
  и сканер теперь видит сам интерпретатор Python. Возврат к обычному образу
  ловят правило D6 в `make lint` и `make check-images` в `make smoke`.
- Go повышен с 1.24 до 1.27: 1.24 уже не получала исправлений безопасности.
- Сборка control plane больше не скачивает build backend мимо lock-файла.
- Конфигурация NATS по умолчанию из официального образа (порт кластера
  с опубликованным паролем) заменена своей.
- `X-Forwarded-Port`, `X-Forwarded-Prefix`, `X-Forwarded-Ssl` и другие
  `X-Forwarded-*` от клиента доходили до приложения: ReverseProxy удаляет
  только `-For`, `-Host`, `-Proto`. Теперь от недоверенных соединений
  удаляются все, а варианты с подчёркиванием (`X_Forwarded_For`) — всегда
  (T1, T18). Правило Semgrep запрещает читать такие заголовки где-либо,
  кроме пакета доверенных прокси.
- События содержат только метод, путь, User-Agent и признак параметров;
  в пути маскируются почта, UUID, JWT, числа и токены (T4). Данные
  атакующего пишутся только как значения JSON — одна строка файла всегда
  одно событие (T19). Файл доступен только пользователю сенсора
  и ротируется: не больше 160 МиБ на диске (T3). При переполнении буфера
  вытесняются старые события, чтобы атакующий не мог скрыть свои
  следующие действия.
- Fail-open отключает только обнаружение, не защиту: запрет `CONNECT`
  и чистка заголовков работают всегда. Паники в обнаружении не переключают
  общий режим — иначе атакующий, найдя вызывающий панику запрос, выключал бы
  обнаружение для всех. События о состоянии сенсора записываются через
  отдельную очередь, которую не вытесняет поток других событий (T3).
- Паника при записи события больше не роняет процесс сенсора.
- Политика не может навредить сайту клиента, даже если её подменили (T15):
  ловушка на `/` запрещена, пути только точные, ответ ловушки не бывает HTML
  или перенаправлением и всегда отдаётся с `nosniff` и `no-store`.
  Разбор отвергает повторяющиеся ключи, неизвестные поля и имена в другом
  регистре. Путь запроса нормализуется перед сравнением: `//.env`,
  `/.env;x=1`, `\.env` и `/.env%00` не обходят ловушку. Ошибка в политике
  не мешает запуску сенсора и каждый раз записывается событием.
- Чужая страница не может вызвать касание ловушки высокой уверенности
  из браузера пользователя (T2): такие ловушки срабатывают только на запросы,
  которые браузер с чужого сайта без preflight не отправит, и на preflight
  к ним отвечает сенсор — без одобрения CORS, даже если приложение одобряет
  его для всех. Политику с ловушкой high или very_high без этой защиты
  сенсор не принимает. Значение cookie-ловушки не записывается никуда.
- `X-Original-URL` и `X-Rewrite-URL` от клиента доходили до приложения:
  по ним IIS, Symfony, Laminas берут путь, и так обходят запреты на пути
  в прокси. Теперь они проходят только от доверенного прокси (T18).
