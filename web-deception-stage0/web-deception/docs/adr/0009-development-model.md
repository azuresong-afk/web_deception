# ADR-0009. Модель разработки с AI-ассистентом

Статус: принято. Дата: 2026-09-21.

## Контекст
Владелец проекта — инженер ИБ, не разработчик. Код пишет Claude Code.
Владелец не может глубоко ревьюить каждую строку.

## Решение
- Роли: владелец — требования, модель угроз, логика обнаружения и реакции,
  ревью с точки зрения безопасности; Claude Code — реализация и объяснения.
- Максимум автоматических проверок в CI, включая собственные правила Semgrep
  по требованиям безопасности проекта (например, запрет логирования
  заголовков Authorization и Cookie).
- Каждое изменение сопровождается объяснением: что, почему, граница доверия,
  как протестировано.
- Внешнее ревью опытным Go-разработчиком после этапа 2 и перед первым клиентом.
- Внешний пентест перед первым платным клиентом.

## Альтернативы
- Нанять разработчика сразу — надёжнее, но дороже и медленнее старт.
- Обойтись без внешнего ревью — дешевле, но недопустимый риск для компонента
  в критическом пути чужого трафика.

## Последствия
Быстрый старт и глубокое понимание продукта владельцем. Бюджет нужно
заложить на внешние ревью и пентест.
