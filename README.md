# Web-Deception

Продукт класса web-deception: встраивает в защищаемое веб-приложение приманки,
с которыми легитимные пользователи никогда не взаимодействуют, и превращает
любое касание приманки в точный сигнал об атаке — с автоматической реакцией
и понятными выводами.

Ключевая идея: обычные средства защиты отвечают на вопрос «этот запрос похож
на атаку?» и неизбежно ошибаются в обе стороны. Приманка отвечает на другой
вопрос — «зачем легитимному пользователю трогать то, чего для него
не существует?». На этот вопрос ложных срабатываний почти не бывает.

> **Статус: в разработке, этап 1 из 10.** Продукт не готов к использованию
> в продакшене. Компоненты создаются последовательно, каждый этап проходит
> ревью с точки зрения безопасности.

## Как это устроено

| Компонент | Язык | Роль |
|---|---|---|
| Сенсор | Go | reverse proxy перед приложением: внедряет приманки, обслуживает фейковые эндпоинты, отправляет события |
| Control plane | Python / FastAPI | корреляция событий в профили атакующих, классификация, решения о реакции, алерты |
| Очередь событий | NATS JetStream | доставка событий от сенсоров, не замедляющая трафик |
| Хранилище | PostgreSQL | события, профили, конфигурация, журнал аудита |

Два требования определяют архитектуру сильнее остальных:

1. **Сенсор стоит в критическом пути чужого трафика.** Поэтому он работает
   в режиме fail-open (при сбое запрос идёт в приложение напрямую), никогда
   не ждёт очередь событий и укладывается в бюджет **+5 мс к p99** задержки
   приложения. Переход в fail-open — сам по себе событие с алертом.
2. **Через сенсор проходят пароли и персональные данные.** Поэтому за пределы
   сенсора уходят только метаданные: метод, путь, статус, размеры, тайминги,
   отпечатки. Тела запросов и заголовки авторизации не логируются нигде
   ([ADR-0007](docs/adr/0007-data-minimization.md)).

## Структура репозитория

```
sensor/          Go: код сенсора
controlplane/    Python: control plane
schemas/         JSON Schema — общий контракт событий между ними
deploy/          Dockerfile'ы и docker compose
test/            интеграционные и e2e тесты (unit-тесты лежат рядом с кодом)
tools/semgrep/   собственные правила статического анализа
scripts/         вспомогательные скрипты для Makefile и хуков
docs/            модель угроз, ADR, глоссарий
```

Обоснование структуры — [ADR-0010](docs/adr/0010-repo-structure.md).

## Разработка

```bash
make          # список доступных команд
```

Проверки перед каждым PR — `make lint`, `make test`, `make security` —
появляются по ходу этапа 1 вместе с кодом, который они проверяют.
Команды, которой ещё нет, в `Makefile` нет: проверка, которая ничего
не проверяет, но показывает «успех», опаснее отсутствующей проверки.

## Лицензия

Файла лицензии нет намеренно. По умолчанию это означает «все права защищены»:
исходный код открыт для чтения, но не является свободным программным
обеспечением. Условия использования будут определены отдельно.
