# Собственные правила Semgrep

Правила из раздела «Запрещено» в [CLAUDE.md](../../CLAUDE.md), превращённые
в автоматическую проверку. Правило, за соблюдением которого следит только
человек, рано или поздно нарушается. Правило, за которым следит CI, — нет.

| Правило | Что ловит | Угроза |
|---|---|---|
| `go-no-sensitive-http-logging` | логирование заголовков целиком, Authorization, Cookie, Set-Cookie, тела, cookies, параметров запроса, полного URL — в том числе через атрибуты и значения slog и `With` | T4 |
| `python-no-sensitive-http-logging` | то же для Python | T4 |
| `go-untrusted-forwarded-headers` | чтение X-Forwarded-*, X-Real-IP и подобных (в том числе с `_` вместо `-`) где-либо, кроме пакета `sensor/internal/forwarded` | T1 |
| `python-untrusted-forwarded-headers` | то же для Python, без исключений | T1 |
| `github-actions-pin-by-sha` | action или workflow подключён не по полному SHA коммита | T12 |
| `github-actions-dangerous-triggers` | события `pull_request_target` и `workflow_run` | T12 |
| `go-mac-compare-constant-time` | сравнение MAC или подписи не за постоянное время | T7 |
| `python-mac-compare-constant-time` | то же для Python | T7 |

Правила про логирование работают в режиме taint: они отслеживают путь данных
через переменные, а не ищут одну строку кода. Поэтому ловится и
`h := r.Header; ...; logger.Info("x", h)`.

## Как устроены тесты

У каждого правила `rules/<правило>.yaml` есть файл с примерами
`rules/<правило>.go`, `.py` или `.test.yml`. Строка `ruleid: <правило>`
означает «на следующей строке правило обязано сработать», строка
`ok: <правило>` — «обязано промолчать». Запуск тестов:

```bash
make security-sast
```

Правило без теста не принимается: оно может не срабатывать вовсе
и при этом показывать «чисто».

## Исключения

Если правило сработало на безопасном месте, над строкой ставится
`// nosemgrep: <правило>` (или `# nosemgrep: <правило>` в Python и YAML),
а над ним — объяснение, почему место безопасно. Пример —
`sensor/cmd/sensor/main_test.go`. Общих исключений в самих правилах нет
намеренно: например, ошибки в Go нельзя считать безопасными целиком,
потому что ошибки разбора содержат входную строку.

## Почему только свои правила

Наборы правил из реестра Semgrep не используются: это код, загружаемый
из интернета при каждом запуске без закрепления версии, и он во многом
повторяет CodeQL. Общий статический анализ делают CodeQL, gosec и ruff,
а Semgrep отвечает только за правила проекта. Подробнее — в
[ADR-0016](../../docs/adr/0016-security-scanning.md).
