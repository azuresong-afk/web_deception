## Активы

- Трафик клиентов, проходящий через сенсор (пароли, токены, персональные данные).
- Доступность защищаемого приложения.
- Целостность конфигурации сенсоров.
- Журнал событий и профили атакующих.
- Секреты продукта: ключ подписи конфигурации, HMAC-ключи canary-токенов,
  токен Telegram-бота.
- Репутация продукта.

## Границы доверия

1. Интернет → сенсор. Весь вход враждебен.
2. Сенсор → control plane. Сенсор работает у клиента и может быть скомпрометирован.
3. Control plane → администратор (дашборд, Telegram).
4. CI/CD → артефакты (образы, релизы).

## Принятые риски

- **R1.** В режиме fail-open обнаружение ослаблено. Под перегрузкой проверяется
  каждый 10-й запрос; запрос, на котором обнаружение упало, уходит
  в приложение без проверки. Принимаем ради доступности приложения клиента,
  компенсируем событием critical о каждом переходе и событием с адресом
  клиента о каждой панике (T3, ADR-0024). Падение процесса целиком
  fail-open внутри процесса не покрывает — это перезапуск контейнера
  и балансировщик (этап 10).
- **R2.** При переполнении буфера события теряются. Принимаем, чтобы не замедлять
  приложение; потери учитываются счётчиком и видны в мониторинге. Теряются
  старые события, а не новые: иначе атакующий, заполнив буфер, скрыл бы свои
  следующие действия. При сбое процесса теряются ещё и события, не сброшенные
  из буфера файла, — доли секунды (ADR-0023).
- **R3.** Атакующий, который знает реальную уязвимость и идёт к ней напрямую,
  не касаясь приманок, обнаружен не будет. Продукт — слой обнаружения,
  а не замена WAF, пентеста и безопасной разработки.
- **R4.** Исходный код продукта публичен, поэтому атакующий может изучить
  логику обнаружения. Принимаем ради бесплатных проверок безопасности
  GitHub и ради того, чтобы стойкость не опиралась на секретность кода
  (ADR-0011). Компенсируется тем, что конкретные приманки генерируются
  под клиента и в репозитории не хранятся.
- **R5.** В базовых образах бывают уязвимости, для которых исправление ещё
  не выпущено. Проверка Trivy на них не падает — обновиться не на что, —
  но показывает их в сводке. После перехода control plane на distroless
  (ADR-0020) это 22 записи уровня HIGH (12 уникальных уязвимостей): в Python
  3.13 из Debian (HTML-парсер, tarfile, разбор XML), в expat, ncurses и
  libuuid. Control plane не разбирает XML, HTML и архивы, утилит монтирования
  в образе нет. Если control plane начнёт разбирать XML, HTML или архивы,
  уязвимости в этих модулях станут достижимыми, и риск нужно пересмотреть.
  Python из Debian отстаёт от upstream по патч-версиям: исправления
  переносятся не все и не сразу. Снижается еженедельным прогоном, который
