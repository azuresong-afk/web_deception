# ADR-0014. Контейнеры: образы, права, сеть, секреты

Статус: принято, частично заменено [ADR-0020](0020-controlplane-distroless.md)
(рантайм control plane). Дата: 2026-09-22.

## Контекст
Все компоненты продукта поставляются в контейнерах, и локальный стек
поднимается через docker compose. Образ — это то, что реально исполняется
у клиента, поэтому решения о нём — решения о безопасности продукта,
а не об удобстве сборки. CLAUDE.md уже запрещает образы с тегом latest
и контейнеры от root; нужно решить остальное и сделать правила проверяемыми.

## Решение

**Базовые образы.**
- Сенсор: сборка на `golang`, рантайм на `gcr.io/distroless/static`. В итоговом
  образе один статический бинарник — ни shell, ни пакетного менеджера,
  ни curl. Размер около 4 МБ.
- Control plane: сборка и рантайм на `python:3.12-slim`. Из рантайма удалён pip.
  Shell остаётся — это известный компромисс, см. «Последствия».
- Все базовые образы — поддерживаемых версий. Go повышен с 1.24 до 1.27:
  1.24 к началу проекта уже не получала исправлений безопасности.

**Закрепление.** Каждый образ закреплён по digest мультиплатформенного
индекса (amd64 и arm64). Тег оставлен рядом для читаемости и для Dependabot.
Директивы `# syntax=` в Dockerfile нет: она скачивает незакреплённый
образ-интерпретатор при каждой сборке.

**Права.** Каждый процесс работает от пользователя с числовым UID, не 0.
В compose для каждого сервиса: `cap_drop: [ALL]`, `no-new-privileges`,
файловая система только для чтения (кроме Juice Shop), лимиты памяти
и числа процессов, ротация логов.

**Проверка здоровья.** Встроена в сами приложения (`sensor healthcheck`,
`python -m webdeception_cp.healthcheck`), потому что curl в образах нет.
Возвращает только 0 или 1: код 2 в проверке здоровья Docker зарезервирован.

**Сеть.** Две сети. `backend` с `internal: true` — без выхода в интернет:
база, очередь, сенсор, control plane. `edge` — для публикации портов на хост.
Уязвимое учебное приложение Juice Shop — только в `edge`: до базы и очереди
ему не дотянуться. Порты публикуются только на `127.0.0.1`.

**Секреты.** Файлами через механизм secrets в compose, а не переменными
окружения: переменные видны в `docker inspect` и `/proc/<pid>/environ`
и наследуются дочерними процессами. Файлы создаёт `make secrets`
с криптографически стойким генератором; существующие не перезаписываются.

**Конфигурация сторонних образов не используется по умолчанию.** Файл
конфигурации NATS из официального образа открывает порт кластера
с опубликованным паролем; вместо него — свой файл.

**Проверка политики как код.** `scripts/check_containers.py` в `make lint`
проверяет compose и Dockerfile на соответствие правилам выше. Каждое правило
имеет тест, в котором оно срабатывает.

## Уточнение к ADR-0013
ADR-0013 утверждал, что lock-файл защищает всю цепочку установки Python.
При сборке образа выяснилось, что это не так: build backend (hatchling)
скачивался в любой свежей версии при каждой сборке и в lock-файл не попадал.
Control plane переведён в режим без сборки пакета (`package = false`),
и теперь при установке исполняется только закреплённое в `uv.lock`.
uv в образ ставится через pip с проверкой контрольных сумм колёс.

## Альтернативы
- **Alpine вместо distroless для сенсора.** Меньше, чем Debian, но в нём есть
  shell и пакетный менеджер — ровно то, что мы хотим убрать.
- **Distroless для control plane.** Убрал бы shell. Отложено: Python в distroless
  берётся из Debian, и его версия не совпадает с нашей 3.12 — переход требует
  отдельного согласования версий. Записано в технический долг.
- **Секреты в `.env`.** Проще, но пароль виден в `docker inspect` любому,
  у кого есть доступ к Docker на машине.
- **Одна сеть для всего.** Проще, но скомпрометированный Juice Shop видел бы
  базу, а база имела бы выход в интернет.
- **Проверка правил только через Semgrep на шаге 6.** Возможно, но свой скрипт
  проверяет нормализованную модель compose от самого Docker — с учётом якорей
  и профилей, чего разбор YAML текстом не даёт.

## Последствия
- Образ сенсора — около 4 МБ, control plane — около 48 МБ.
- В образе control plane есть shell. Атакующий с выполнением кода в нём
  получит больше инструментов, чем в сенсоре. Компенсировано: нет pip, код
  приложения недоступен на запись, файловая система только для чтения,
  нет capabilities, нет выхода в интернет из сети backend.
- Обновление базового образа — это смена digest, то есть отдельное изменение
  с отдельным ревью. Без Dependabot (шаг 6) digest'ы устареют, и мы будем
  надёжно закреплены на уязвимых версиях. Закрепление без обновления хуже,
  чем кажется.
- Для `make lint` нужен docker CLI.
