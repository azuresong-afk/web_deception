# ADR-0016. Проверки безопасности в CI

Статус: принято. Дата: 2026-09-22.

## Контекст
Проверки качества (ADR-0015) отвечают на вопрос «правильно ли написан код».
Нужен второй слой — «безопасен ли он»: секреты в истории, уязвимые
зависимости, опасные конструкции в коде, уязвимые пакеты в образах.
И правила из раздела «Запрещено» в CLAUDE.md должны проверяться машиной,
а не памятью.

Отдельный вопрос — цепочка поставки самих сканеров. Сканер видит весь
исходный код. Сканер, скачанный без закрепления версии и работающий
с доступом в сеть, — сам по себе канал утечки.

## Решение

| Слой | Инструмент | Когда падает | Где |
|---|---|---|---|
| секреты | gitleaks | любой секрет во всей истории git | всегда |
| уязвимости Go | govulncheck | наш код вызывает уязвимую функцию | изменён Go |
| уязвимости Python | pip-audit | уязвимая версия в uv.lock, включая dev | изменён Python |
| правила проекта | Semgrep | нарушение правил из CLAUDE.md | всегда |
| общий SAST | CodeQL | уязвимость по потоку данных | всегда, отдельный workflow |
| Dockerfile | hadolint + наша политика | небезопасная конструкция | изменены образы |
| образы | Trivy | HIGH или CRITICAL, для которой есть исправление | изменены образы |
| обновления | Dependabot | — (присылает PR) | еженедельно |

**gitleaks** проверяет всю историю, а не текущие файлы, и скрывает найденные
значения в выводе: логи CI публичного репозитория видны всем. Своё правило
по пути ловит файл из каталога локальных секретов, добавленный через
`git add -f`, — у случайных паролей нет узнаваемого формата.

**govulncheck** падает только на достижимых уязвимостях: уязвимая версия
модуля, функцию которого мы не вызываем, упоминается для сведения.

**pip-audit** проверяет все группы зависимостей, включая разработку:
инструменты разработки исполняются в CI и на машинах разработчиков.

**Semgrep — только собственные правила** проекта в `tools/semgrep/rules/`,
у каждого есть тест с примерами нарушений и корректного кода. Правила
из реестра Semgrep не используются. Общий статический анализ делают CodeQL,
gosec и ruff, а Semgrep отвечает только за правила проекта. Метрики
отключены. Список исключений задан явно в `.semgrepignore`: список
по умолчанию молча исключает все тесты.

Исключение из правила Semgrep ставится комментарием `nosemgrep` строкой
выше, и над ним обязательно объяснение, почему это место безопасно.

**CodeQL** — набор `security-extended` для Go, Python и самих workflow,
в отдельном workflow: только ему нужно право `security-events: write`.

**Trivy** получает образы файлами (`docker save`), а не через сокет Docker:
смонтированный сокет — это полный контроль над хостом. Проверка падает на
уязвимостях HIGH и CRITICAL, для которых вышло исправление. Уязвимости без
исправления выводятся в сводке, но проверку не валят — это принятый
риск R5 в модели угроз.

**Сканеры работают в контейнерах**, описанных в `tools/scanners/compose.yaml`:
образы закреплены по digest (и обновляются Dependabot), процессы не от root,
файловая система только для чтения, без capabilities и **без сети** — кроме
Trivy, которому нужна база уязвимостей. Эти контейнеры проверяет тот же
скрипт политики, что и контейнеры продукта. Инструменты на Go (gitleaks,
govulncheck) — модули в `tools/` с контрольными суммами, как линтеры.

**Dependabot** обновляет все шесть экосистем: actions, модули Go, uv, pip,
Dockerfile, compose. Раз в неделю, с группировкой мелких обновлений
и с **выдержкой 7 дней** после публикации версии: вредоносные релизы
от угнанных учётных записей сопровождающих обычно обнаруживают и отзывают
за несколько дней. На срочные обновления безопасности выдержка не действует.

**Еженедельный прогон** CI и CodeQL по main без изменений в коде:
уязвимости публикуются каждый день, и зависимость, чистая сегодня,
через неделю может оказаться уязвимой.

## Альтернативы
- **Наборы правил из реестра Semgrep** (`p/default`, `p/golang`). Много правил
  бесплатно, но это код, загружаемый из интернета при каждом запуске без
  закрепления версии, и он во многом дублирует CodeQL.
- **Падать на всех HIGH, включая неисправленные.** Сейчас это 44 уязвимости
  в базовом образе control plane, для которых нет исправления. CI был бы
  красным постоянно, и красный цвет перестал бы что-либо значить.
- **Trivy через `/var/run/docker.sock`.** Стандартный способ из документации,
  но процесс с доступом к сокету управляет всем хостом.
- **Коммерческие SCA (Snyk и подобные).** Требуют учётной записи и отправляют
  список зависимостей или код третьей стороне.
- **Renovate вместо Dependabot.** Гибче, но это стороннее приложение GitHub
  с правом записи в репозиторий; Dependabot встроен в GitHub.

## Последствия
- CI дольше: Trivy скачивает базу уязвимостей, Semgrep — образ около 500 МБ.
- Раз в неделю появляются PR от Dependabot, их нужно ревьюить. Группировка
  сводит их к нескольким на неделю.
- Сканеры в контейнерах: для `make security` локально нужен Docker.
- Требуются настройки репозитория, которые нельзя задать из кода:
  Dependabot alerts и security updates, secret scanning с push protection,
  и выключенный «default setup» CodeQL — он конфликтует с нашим workflow.
- GitHub отключает запуск по расписанию в репозиториях без активности
  60 дней. После длинной паузы еженедельный прогон нужно включить заново.
