# ADR-0020. Control plane на distroless и Python 3.13

Статус: принято. Дата: 2026-09-24.

Частично заменяет [ADR-0014](0014-containers.md): там рантайм control plane —
`python:3.12-slim`, а distroless отложен в технический долг.

## Контекст

Образ control plane был построен на `python:3.12-slim` — урезанном, но
полноценном Debian. В нём 87 пакетов, среди них `sh`, `bash`, `apt`, `dpkg`,
`perl`. pip мы удалили ещё на этапе 1, остальное оставалось.

Это давало две проблемы:

- **Инструменты для атакующего.** При выполнении кода в control plane
  готовые эксплойты запускают `/bin/sh -c "..."`, ставят свои утилиты через
  `apt`, поднимают обратное соединение через `perl` или `bash`.
- **Шум в отчёте об уязвимостях.** Trivy находил 44 уязвимости HIGH без
  исправлений в 17 пакетах: util-linux, ncurses, perl, systemd, login.
  Наш код ни один из них не использует. Еженедельный отчёт с одними
  и теми же 44 строками приучает его не читать (риск R5).

На этапе 1 переход отложили: Python в distroless берётся из Debian,
а Debian 13 поставляет 3.13, тогда как control plane был на 3.12. Сейчас
в control plane почти нет кода, и согласовать версии дешевле всего именно
сейчас: с этапа 3 появятся драйвер PostgreSQL и `cryptography` со своими
системными библиотеками.

## Решение

1. **Рантайм — `gcr.io/distroless/python3-debian13:nonroot`**, по digest
   индекса образа (все архитектуры). В образе интерпретатор Python, glibc,
   OpenSSL и несколько библиотек. Нет shell, менеджера пакетов, perl, curl.
2. **Python 3.13 во всём control plane**: `requires-python`, `.python-version`
   (по нему CI ставит Python), mypy, ruff, `uv.lock`. Разработка и тесты
   на той же минорной версии, на которой код работает в продакшене.
3. **Сборка — на `python:3.13-slim`**, рантайм — на Python 3.13 из Debian.
   Патч-версии различаются, минорная совпадает, а внутри минорной версии
   совпадают формат байткода и двоичный интерфейс пакетов с машинным кодом.
4. **Зависимости — в обычный каталог** `/app/deps` через
   `uv pip install --target`, а не в виртуальное окружение: окружение
   привязано к пути интерпретатора сборки, а в рантайме Python лежит
   в другом месте. По-прежнему строго по `uv.lock`, с проверкой хешей
   и без сборки из исходников.
5. **`PYTHONSAFEPATH=1`**: Python не ищет модули в текущем каталоге.
   Закрывает подмену стандартного модуля файлом, оказавшимся в рабочем
   каталоге.
6. **Пользователь 65532** (`nonroot` из distroless), как у сенсора, вместо 10001.
7. **Проверки, чтобы не откатиться назад:**
   - правило D6 в `make lint`: финальная стадия любого Dockerfile
     в `deploy/docker` построена на distroless, и не на отладочном варианте
     (`:debug` — в нём busybox с shell в `/busybox/sh`);
   - `make check-images` в `make smoke` (и в CI): в собранных образах
     продукта не запускается ни `sh` (включая `/busybox/sh`), ни `bash`,
     ни `perl`, ни `apt-get`, ни `pip`, ни `curl`.

## Результат

| | До | После |
|---|---|---|
| Пакетов Debian | 87 | 38, без shell и утилит |
| Размер образа (сжатый) | 47,5 МБ | 26,2 МБ |
| HIGH по Trivy, всего | 44 | 22 |
| HIGH с доступным исправлением | 0 | 0 |
| Пакеты с уязвимостями | util-linux, ncurses, perl, systemd, login… (17) | Python 3.13, expat, ncurses, libuuid (8) |

Важная тонкость: сравнение «44 → 22» не совсем честное в пользу старого
образа. Там Python был собран из исходников в `/usr/local`, и Trivy его
**не видел вообще** — уязвимости самого интерпретатора в отчёт не попадали.
Теперь Python — пакет Debian, и сканер проверяет и его. То есть новый отчёт
одновременно короче и полнее.

Оставшиеся 12 уязвимостей (22 записи — одна уязвимость затрагивает несколько
пакетов): разбор XML (expat), HTML-парсер и модуль tarfile в Python, ncurses,
утилиты монтирования из util-linux (в образе только библиотека libuuid,
самих утилит нет). Control plane XML, HTML и архивы не разбирает. Записано
в риск R5.

## Альтернативы

- **Оставить `python:slim` и удалить из него shell и утилиты вручную.**
  `bash`, `dpkg`, `perl-base` помечены в Debian как обязательные; удаление
  ломает систему пакетов, и каждое обновление базового образа пришлось бы
  проверять заново. Хрупко.
- **Скопировать Python из официального образа в `distroless/cc`.** Свежая
  патч-версия Python, но интерпретатор снова невидим для Trivy, а набор
  системных библиотек для него (libssl, libffi, zlib, libsqlite) пришлось бы
  подбирать и поддерживать самим.
- **Chainguard Python.** Минимальный образ с частыми обновлениями,
  но бесплатный вариант на момент решения рассчитан на тег `latest`,
  а закреплённые версии — платная подписка. Конфликтует с правилом
  «без latest» и добавляет поставщика ради одного образа.
- **Alpine.** Меньше Debian, но в нём есть shell и пакетный менеджер —
  ровно то, что мы убираем. К тому же musl вместо glibc: не для всех
  пакетов есть готовые колёса, и часть пришлось бы собирать из исходников.

## Последствия

- Зайти в контейнер через `docker exec … sh` нельзя. Для отладки —
  логи, проверка здоровья и `docker debug` локально.
- Python в рантайме отстаёт от свежего upstream по патч-версиям
  (Debian 3.13.5 против 3.13.15 в официальном образе на момент решения).
  Исправления безопасности Debian переносит в свою версию, но не все и не сразу —
  отсюда уязвимости без исправлений в отчёте. Обновление приходит со сменой
  digest образа distroless, за ним следит Dependabot.
- Проверка D6 не пропустит Dockerfile продукта без distroless. Учебные цели
  (ADR-0019) — намеренно уязвимые чужие приложения — будут лежать отдельно
  от `deploy/docker` и под D6 не попадут.
