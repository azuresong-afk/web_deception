# Как читать Go-код продукта

Для кого: вы читаете код, чтобы ревьюить его с точки зрения безопасности,
а не чтобы писать. Весь язык знать не нужно. Хватит примерно пятнадцати
конструкций — все они уже есть в сенсоре, и примеры ниже взяты из него.

Как пользоваться: откройте рядом `sensor/cmd/sensor/main.go`
и `sensor/internal/admin/server.go` и находите в них каждую конструкцию.
В конце — чек-лист ревью: он пригодится на каждом PR этапа 2.

---

## 1. Файлы и пакеты

```go
package admin

import (
	"net/http"

	"github.com/azuresong-afk/web_deception/sensor/internal/config"
)
```

- **Пакет** — это каталог. Все файлы каталога начинаются с одинаковой
  строки `package`. `package main` — особый: из него собирается программа.
- **import** — что использует файл. Короткие имена (`net/http`) — стандартная
  библиотека Go; длинные, с адресом репозитория, — наш код или зависимости.
- Каталог **`internal/`** Go не даёт импортировать снаружи модуля. Это
  проверяет компилятор, а не договорённость.
- **Заглавная буква = видно снаружи пакета.** `Load`, `Config`, `NewServer` —
  доступны другим пакетам. `validateAddr`, `writePlain` — только внутри своего.
  Для ревью это значит: строчную функцию можно вызвать только из этого
  же каталога, и её поверхность ограничена им.

## 2. Функции и ошибки

```go
func Load(getenv Getenv) (*Config, error) {
```

Читается так: функция `Load` принимает `getenv` типа `Getenv` и возвращает
**два** значения — указатель на `Config` и ошибку. Тип пишется после имени.

В Go нет исключений. Ошибка — обычное значение, которое функция возвращает,
а вызывающий обязан проверить:

```go
cfg, err := config.Load(os.Getenv)
if err != nil {
	fmt.Fprintf(os.Stderr, "ошибка конфигурации: %v\n", err)
	os.Exit(2)
}
```

`nil` — «ничего», аналог `None` в Python. `err != nil` — «ошибка есть».

Что искать на ревью:

- **`_ =` или `_, _ =`** — ошибку сознательно выбросили. Каждое такое место
  обязано иметь рядом комментарий «почему». Пример из `writePlain`: ошибку
  записи игнорируем, потому что клиент уже отключился и сделать с этим нечего.
- **`fmt.Errorf("...: %w", err)`** — ошибку заворачивают в новую
  с пояснением, сохраняя исходную. **`errors.Is(err, X)`** — проверка,
  что где-то внутри лежит именно ошибка `X`.

## 3. Переменные и нулевые значения

```go
cfg, err := config.Load(os.Getenv) // := объявить и присвоить
var ready atomic.Bool              // var — объявить с нулевым значением
```

У каждого типа есть **нулевое значение**: `0`, `""`, `false`, `nil`.
Для безопасности это важнее, чем кажется. Нулевое значение таймаута —
`0`, а в `http.Server` ноль означает **«ждать бесконечно»**. Поэтому
`&http.Server{}` без явных таймаутов — это открытая дверь для Slowloris,
и в `admin.NewServer` все таймауты заданы явно.

## 4. Структуры, указатели, методы

```go
type Config struct {
	AdminAddr       string
	ShutdownTimeout time.Duration
}

cfg := &Config{AdminAddr: defaultAdminAddr}

func (c *Config) Warnings() []string { ... }
```

- **`struct`** — набор полей, как запись в таблице.
- **`&Config{...}`** — создать и получить **указатель** (`*Config`).
  Все, у кого есть указатель, видят один и тот же объект, и изменения
  одного видны всем.
- **`func (c *Config) Warnings()`** — метод: функция, привязанная к типу.
  `c` — объект, у которого метод вызвали (как `self` в Python).

## 5. Срезы и словари

```go
var out []string              // срез — список переменной длины
out = append(out, "текст")    // добавить элемент

var allowedPaths = map[string]struct{}{"/healthz": {}, "/readyz": {}}
if _, ok := allowedPaths[r.URL.Path]; !ok { ... }
```

- `map[string]struct{}` — множество: важны только ключи.
- Чтение отсутствующего ключа не падает, а возвращает нулевое значение;
  второй результат `ok` говорит, был ли ключ.
- **Опасно:** запись в `map` из нескольких горутин одновременно без
  блокировки роняет **весь процесс** (`fatal error: concurrent map writes`).
  Для сенсора это отказ в обслуживании. Такие ошибки ловит `go test -race`,
  который у нас запускается в `make test`.

## 6. Интерфейсы и обёртки обработчиков

`http.Handler` — интерфейс: любой тип с методом `ServeHTTP(w, r)` может
обрабатывать HTTP-запросы. На этом построены **обёртки** (middleware):

```go
func onlyKnownPaths(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if _, ok := allowedPaths[r.URL.Path]; !ok {
			writePlain(w, http.StatusNotFound, "not found")
			return // дальше запрос не идёт
		}
		next.ServeHTTP(w, r) // передать следующему в цепочке
	})
}
```

Для ревью: цепочка обёрток — это порядок, в котором применяются проверки.
Порядок имеет значение. Ограничение размера должно стоять **до** разбора,
а не после; fail-open — **снаружи** кода, который может упасть.

## 7. defer

```go
ctx, stop := signal.NotifyContext(ctx, os.Interrupt, syscall.SIGTERM)
defer stop()
```

`defer` выполняет вызов при выходе из функции — любом: обычном, по ошибке,
по панике. Им освобождают ресурсы. Что искать: `resp, err := client.Do(req)`
без `defer resp.Body.Close()` — утечка соединений, которая под нагрузкой
заканчивается исчерпанием файловых дескрипторов.

## 8. Горутины и каналы

```go
serveErr := make(chan error, 1) // канал на один элемент
go func() {                     // запустить параллельно
	serveErr <- srv.Serve(ln)   // положить результат в канал
}()

select {                        // ждать первое из нескольких событий
case err := <-serveErr:
	return err
case <-ctx.Done():
}
```

- **Горутина** (`go f()`) — лёгкий параллельный поток. Их тысячи, и каждая
  ест память. Горутина, которая никогда не завершится, — **утечка**, а
  утечка, которую атакующий может запускать запросами, — отказ в обслуживании.
- **Канал** — труба между горутинами. Запись в полный канал **блокирует**
  пишущего, пока кто-то не прочитает.

Неблокирующая запись — ключевой приём продукта. Так выполнено правило
«сенсор никогда не ждёт очередь событий» (`event.Recorder.Emit`, шаг 6):

```go
select {
case events <- ev: // место в буфере есть — положили
	return
default: // буфер полон — не ждём
}
select {
case <-events: // вытесняем самое старое событие
	dropped.Add(1)
default:
}
```

`select` с веткой `default` не ждёт: если ни одна операция не готова
сразу, выполняется `default`. Что искать при ревью: запись в канал без
`select` и `default` в пути запроса — это ожидание.

## 9. context.Context

`ctx` — первый параметр многих функций. Он несёт отмену и срок: «прекрати,
клиент ушёл» или «у тебя 5 секунд». `context.WithTimeout` — дать срок,
`ctx.Done()` — канал, который закрывается при отмене.

Что искать: сетевой вызов без контекста и без таймаута может висеть вечно.
`http.Get(url)` использует клиент **без таймаута** — в нашем коде так
делать нельзя.

## 10. panic и recover

`panic` — аварийная остановка горутины (обращение к `nil`, выход за границы
среза). Паника в горутине, которую никто не перехватил, **убивает весь
процесс**. `net/http` перехватывает паники в обработчиках запросов, но не
в горутинах, которые обработчик запустил сам.

`recover` перехватывает панику внутри `defer`. На шаге 7 это основа
fail-open: паника в коде приманок перехватывается, запрос уходит
в приложение, а переход в fail-open становится событием.

## 11. Тесты

Тесты лежат рядом с кодом в файлах `*_test.go`. Сокращённый фрагмент
из `sensor/internal/config/config_test.go`:

```go
func TestLoadRejectsInvalidValues(t *testing.T) {
	tests := []struct {
		name         string            // название случая
		env          map[string]string // что подаём на вход
		wantContains string            // что обязано быть в тексте ошибки
	}{
		{"порт вне диапазона", map[string]string{"SENSOR_ADMIN_ADDR": "127.0.0.1:70000"}, "диапазона"},
		{"слишком большая длительность", map[string]string{"SENSOR_SHUTDOWN_TIMEOUT": "10m"}, "не должен превышать"},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			cfg, err := Load(envMap(tt.env))
			if err == nil {
				t.Fatalf("ожидалась ошибка, получена конфигурация %+v", cfg)
			}
			// ...
		})
	}
}
```

Это **табличный тест**: таблица случаев и один цикл их проверки. Таблица
читается как спецификация поведения, даже без знания Go: «адрес с портом
70000 должен быть отвергнут, и в ошибке должно быть слово „диапазона“».

Что искать на ревью:

- **Отрицательные случаи.** Есть ли в таблице то, что пришлёт атакующий:
  пустое значение, огромное, с `../`, с управляющими символами?
- **Падает ли тест без нового кода.** Тест, который проходит и с ошибкой,
  и без неё, ничего не доказывает.
- `httptest.NewRecorder()` и `httptest.NewServer()` — ненастоящие HTTP-клиент
  и сервер для тестов, без сети.
- `func FuzzX(f *testing.F)` — **фаззинг**: Go сам генерирует миллионы входов
  и ищет те, на которых код падает. Появится на шагах 6 и 10.

## 12. Где в коде данные атакующего

Почти всё, что приходит от атакующего, доступно через `r *http.Request`:

| Что в коде | Что это | Как обращаться |
|---|---|---|
| `r.URL.Path` | путь, уже раскодированный (`%2e` → `.`) | враждебен; сравнивать после нормализации |
| `r.URL.RawPath`, `r.RequestURI` | путь в том виде, как пришёл | враждебен; в приложение передаётся без изменений |
| `r.URL.RawQuery`, `r.URL.Query()` | параметры запроса | враждебны; **в лог нельзя** |
| `r.Header.Get("...")` | заголовки | враждебны; `Authorization`, `Cookie` — **в лог нельзя** |
| `X-Forwarded-For` и подобные | «настоящий IP клиента» по словам клиента | **только** через пакет `forwarded` (доверенные прокси, шаг 5), иначе срабатывает правило Semgrep |
| `r.Host` | заголовок `Host` | враждебен; **никогда** не использовать, чтобы решить, куда проксировать |
| `r.Body` | тело запроса | враждебно; читать только с ограничением размера, **в лог нельзя никогда** |
| `r.RemoteAddr` | адрес TCP-соединения | его нельзя подделать, но это может быть адрес прокси, а не клиента |
| `r.Method` | метод | враждебен; разрешённые методы перечислять явно |

Ответ защищаемого приложения — **частично** доверенный: приложение наше,
но в ответе может оказаться то, что атакующий в нём сохранил (хранимый XSS).
Поэтому код правки HTML на шаге 10 тоже считается кодом, обрабатывающим
враждебный вход.

## 13. Чек-лист ревью Go-кода

Для каждого PR, где меняется Go-код, пройдитесь по списку. Команда
`git diff main -- sensor/ | grep -n 'ШАБЛОН'` помогает найти места.

| Что искать в diff | Чем опасно | Как должно быть |
|---|---|---|
| `io.ReadAll(r.Body)` | тело без предела съест память | `http.MaxBytesReader` или `io.LimitReader` перед чтением |
| `&http.Server{` без `ReadHeaderTimeout` | Slowloris | все таймауты заданы явно |
| `http.Get(`, `http.DefaultClient`, `&http.Client{}` без `Timeout` | вечное ожидание | свой клиент с таймаутами |
| `_ =`, `_, _ =` | потерянная ошибка | комментарий «почему» рядом |
| `go func()` внутри обработчика | утечка горутин под нагрузкой | ограничение числа и отмена через контекст |
| общий `map` без `sync.Mutex` | падение всего процесса | мьютекс или `atomic`, тест с `-race` |
| `==` для подписи, токена, пароля | атака по времени | `hmac.Equal`, `subtle.ConstantTimeCompare` |
| `text/template` для HTML | XSS | `html/template` |
| `filepath.Join(base, ввод)` | выход за каталог (`../`) | `os.Root` или строгая проверка |
| `exec.Command` с данными запроса | исполнение команд | не использовать |
| `slog.`/`log.` рядом с `r.Header`, `r.Body`, `RawQuery` | утечка секретов в лог | только метаданные; правило Semgrep |
| `InsecureSkipVerify: true` | отключена проверка TLS | запрещено вне тестов |
| `math/rand` для токенов и сидов | предсказуемые значения | `crypto/rand` |
| `//nolint`, `// nosemgrep` | отключённая проверка | обоснование в той же строке или строкой выше |
| `panic(` в нашем коде | падение процесса | возвращать ошибку |
| `int32(x)`, `uint16(x)` после разбора числа | переполнение | проверка диапазона до преобразования |

## 14. Как посмотреть самому

```bash
make test-go                                  # все тесты сенсора с -race
cd sensor && go test ./internal/admin -v      # один пакет, подробно
cd sensor && go test ./... -run TestLoad -v   # один тест по имени
cd sensor && go doc net/http.Server           # документация по типу
```

Документация стандартной библиотеки: <https://pkg.go.dev/std>.
