# Этап 2, шаг 8. Политика как данные и первые ловушки

> Снимок на момент шага: 2026-09-24. Решение — в
> [ADR-0025](../../adr/0025-policy-format.md). Текущее состояние —
> в [guide.md](../../guide.md), раздел «Сенсор».

## Что и зачем

До этого шага сенсор умел всё, кроме главного: обнаруживать. Теперь у него
есть ловушки — пути, которые трогают только атакующие и сканеры: `/.env`,
`/.git/config`, `/backup.sql`. Касание записывается событием с адресом
клиента, а сенсор отвечает фейковым файлом вместо приложения.

Ловушки задаются не кодом, а файлом политики (ADR-0018). Это тот же
формат, который на этапе 5 будет редактироваться в веб-интерфейсе, а на
этапе 3 — приходить с control plane. Control plane может быть взломан
(угроза T15), поэтому сенсор не верит политике на слово. Он проверяет её
сам и строго: всё, что пропустила проверка, окажется в ответах сайту
клиента.

## Понятия

- **Политика обнаружения** — JSON-документ с ловушками.
- **Ловушка** — точный путь; касание — запрос к нему.
- **Режим наблюдения** (`observe`) — касание записывается, запрос идёт
  в приложение.
- **Нормализация пути** — `//.env`, `/./.env`, `/.env;x` → `/.env`.
- **Последняя валидная версия** — неверная новая политика не применяется,
  работает прежняя.
- **Атомарная замена** — политика меняется целиком, одной операцией.
- **SIGHUP** — сигнал «перечитай настройки».

Все — в [глоссарии](../../glossary.md).

## Как это работает

```
файл политики ──► Parse: JSON v2 строго ──► validate: все ошибки ──► Compiled
                    │                          │                        │
                    └── ошибка ────────────────┴──► policy_rejected     │
                                                    остаётся прежняя     ▼
                                                            atomic.Pointer в Detector
                                                                        │
запрос ─► CONNECT? ─► Guard ─► Detector.Inspect:                        │
                                NormalizePath(r.URL.Path) ─► поиск в карте
                                ├─ нет ловушки ─► прокси ─► приложение
                                ├─ observe ─► событие ─► прокси ─► приложение
                                └─ enforce ─► событие ─► ответ ловушки
```

## Разбор кода

### Разбор JSON: `Parse` в `policy/policy.go`

```go
if len(data) > MaxPolicyBytes {
	return nil, fmt.Errorf("политика больше %d байт", MaxPolicyBytes)
}
var p Policy
if err := json.Unmarshal(data, &p, json.RejectUnknownMembers(true)); err != nil {
```

Здесь `json` — это `encoding/json/v2`, новый пакет стандартной библиотеки
Go. Выбран за строгость. Прежний `encoding/json`:

- при повторяющемся ключе молча берёт **последнее** значение. Администратор
  видит в файле `"mode": "observe"`, а ниже, через сорок строк, случайно
  осталось `"mode": "enforce"` — и ловушка отвечает вместо приложения;
- принимает `"Path"` как `path`, без учёта регистра;
- без специальной настройки пропускает неизвестные поля. Опечатка
  `"confidense"` дала бы правило без уверенности, выглядящее настроенным.

Новый пакет всё это отвергает, а с `RejectUnknownMembers(true)` — и
неизвестные поля. Зависимость не нужна: пакет стандартный.

### Проверка: `validate`

```go
var errs []error
add := func(format string, args ...any) {
	if len(errs) < maxReportedErrors {
		errs = append(errs, fmt.Errorf(format, args...))
	}
}
```

Проверка не останавливается на первой ошибке, а собирает до 20.
Администратор исправит всё за раз, а не по одной ошибке на перезагрузку.
`errors.Join` в конце склеивает их в одну ошибку.

```go
if !allowedStatus[r.Status] {
	add("%s.response.status: допустимы 200, 401, 403, 404, 500", at)
}
if _, ok := respond.TrapContentTypes[r.ContentType]; !ok {
```

Список **разрешённого**, а не запрещённого. Разрешены 200, 401, 403,
404, 500. Запрещать «3xx» было бы хуже: список запрещённого всегда что-то
забывает. Перенаправления исключены, потому что `302` с адресом из политики —
это открытый редирект на сайте клиента. `text/html` исключён, потому что
HTML из политики — хранимый XSS на сайте клиента.

### Путь ловушки: `validatePath`

```go
case p == "/":
	return errors.New("ловушка на «/» перехватила бы главную страницу")
case NormalizePath(p) != p:
	return fmt.Errorf("запишите в нормализованном виде: %q", NormalizePath(p))
```

Первое — очевидная защита сайта. Второе тоньше. Путь запроса сравнивается
после нормализации. Если в политике записано `/.env/`, нормализованный
запрос `/.env` с ним никогда не совпадёт. Ловушка выглядела бы работающей
и не ловила бы ничего. Поэтому такая запись — ошибка с подсказкой, как
записать правильно.

### Нормализация: `NormalizePath`

```go
if i := strings.IndexByte(p, 0); i >= 0 {
	p = p[:i]
}
p = strings.ReplaceAll(p, `\`, "/")
```

Каждая строка — приём обхода, который закрывает нормализация:

- нулевой байт: `/.env%00.png` — часть серверов и языков обрезает строку
  на нём, и для них это `/.env`;
- обратная косая черта: `\.env` — для IIS это разделитель пути.

```go
if strings.IndexByte(p, ';') >= 0 {
	segs := strings.Split(p, "/")
	for i, s := range segs {
		if j := strings.IndexByte(s, ';'); j >= 0 {
			segs[i] = s[:j]
		}
	}
	p = strings.Join(segs, "/")
}
```

`/.env;jsessionid=1` — Tomcat понимает `;…` как параметры сегмента,
и для приложения на Java это `/.env`.

```go
return path.Clean(p)
```

`path.Clean` из стандартной библиотеки убирает `//` и `/./`, разрешает
`/../` и отбрасывает завершающий `/`. Процентную запись (`/%2eenv`) уже
раскодировал сервер Go в `r.URL.Path`.

Нормализация — **только для сравнения**. В приложение уходит путь как есть
(ADR-0021). Фаззинг-тест проверяет два свойства: результат всегда
начинается с `/`, и повторная нормализация его не меняет.

### Касание: `Inspect` в `decoy/decoy.go`

```go
p := d.current.Load()
trap, ok := p.Match(r.URL.Path)
if !ok {
	return false
}
```

`current` — `atomic.Pointer`: политика читается одной атомарной операцией.
Если в этот момент идёт перезагрузка, запрос получит либо старую политику
целиком, либо новую целиком. `Match` — нормализация и поиск в карте:
время не зависит от числа ловушек.

```go
ev := event.New(event.TypeDecoyTouch, severity(trap.Confidence))
ev.Client = event.ClientFrom(d.trust.Resolve(r))
ev.Request = event.RequestFrom(r)
ev.Data = map[string]string{"decoy_id": trap.ID, ...}
d.events.Emit(ev)
```

Сначала событие, потом ответ — по договору `Detector` из шага 7: сначала
решить, потом писать. Тело запроса не читается.

```go
if trap.Mode == policy.Observe {
	d.Stats.Observed.Add(1)
	return false
}
respond.Trap(w, trap.Response.Status, trap.Response.ContentType, trap.Response.Body)
return true
```

`false` означает «я не ответил, веди запрос дальше в приложение». Так
работает режим наблюдения.

### Ответ ловушки: `respond.Trap`

```go
ct, ok := TrapContentTypes[contentType]
if !ok {
	ct = "application/octet-stream"
}
h.Set("Content-Type", ct)
h.Set("X-Content-Type-Options", "nosniff")
h.Set("Cache-Control", "no-store")
```

Три заголовка ставит сенсор, а не политика. `nosniff` не даёт браузеру
угадать HTML в тексте ловушки. `no-store` не даёт CDN закэшировать ответ.
Без него следующий сканер получил бы фейковый `.env` из кэша CDN,
и сенсор этого касания не увидел бы. Неизвестный тип (его отвергла бы
проверка) — `octet-stream`: вторая линия защиты на случай ошибки в первой.

### Загрузка: `Startup` и `Reload` в `decoy/loader.go`

```go
func (l *Loader) Startup() {
	if l.loadFile() {
		return
	}
	c, _, err := policy.LoadFile(l.cacheFile)
	switch {
	case err == nil:
		l.apply(c, "last_valid")
```

При запуске: файл администратора, а если он неверен — копия последней
валидной. Копия читается тем же `LoadFile` с той же проверкой. Её мог
испортить сбой диска или кто-то чужой, и доверять ей больше, чем файлу,
нельзя.

Ошибка в политике не мешает запуску. Это отличается от слоя запуска: там
неверный адрес приложения — отказ стартовать. Разница в последствиях.
Адрес приложения — граница доверия, и ошибка в нём — трафик не туда.
Опечатка в тексте фейкового `.env` — не повод ронять сайт.

```go
func (l *Loader) loadFile() bool {
	c, raw, err := policy.LoadFile(l.file)
	if err != nil {
		l.reject(err)
		return false
	}
	l.apply(c, "file")
	if err := policy.WriteCache(l.cacheFile, raw); err != nil {
```

Копия пишется **только после** успешной проверки. Если записать её раньше,
неверная политика стала бы «последней валидной».

### Атомарная запись копии: `WriteCache` в `policy/file.go`

```go
tmp, err := os.CreateTemp(dir, ".policy-*.tmp")
...
if err = errors.Join(tmp.Sync(), tmp.Close()); err != nil {
...
if err = os.Rename(tmp.Name(), path); err != nil {
```

Временный файл в том же каталоге, `Sync` — данные на диске, потом
переименование поверх. Переименование в пределах каталога атомарно. Сбой
посреди записи оставит прежнюю копию целой, а не половину новой.

### SIGHUP: `main.go`

```go
hup := make(chan os.Signal, 1)
signal.Notify(hup, syscall.SIGHUP)
```

Эти строки стоят в самом начале запуска. По умолчанию Go при `SIGHUP`
**завершает** процесс. Без обработчика `make policy-reload` не перечитал бы
политику, а уронил бы сенсор, а с ним и сайт. Мутационная проверка это
подтвердила: без этой строки тестовый процесс погибает от сигнала.

## Находка при проверке руками

Первая версия монтировала в compose один файл:
`../policy/demo.json:/etc/sensor/policy.json:ro`. Проверяя перезагрузку,
я правил файл через `sed -i` и отправлял `SIGHUP`. Сенсор писал в лог
«получен SIGHUP», но политика не менялась.

Причина в Docker. Отдельно смонтированный файл привязан к самому файлу,
а не к имени. `sed -i` и большинство редакторов сохраняют через замену:
пишут новый файл и переименовывают его поверх старого. Контейнер продолжает
видеть старый, уже удалённый файл. Администратор правил бы политику,
а сенсор её не видел бы.

Исправлено: монтируется каталог `../policy:/etc/sensor/policy:ro`. Замена
файла внутри каталога видна контейнеру.

## Граница доверия

| Данные | Откуда | Что с ними делается |
|---|---|---|
| путь запроса | атакующий | только нормализуется и ищется в карте; в ответ не попадает |
| политика | администратор, с этапа 3 — control plane, который может быть взломан | строгий разбор, проверка пределов и запретов; при ошибке — прежняя |
| копия последней валидной | сенсор | `0600`, атомарная запись, проверка при чтении |
| ответ ловушки | политика | тип только из списка, `nosniff`, `no-store` — от сенсора |

## Что может пойти не так

- **T15 — ловушка на настоящем пути приложения.** Сенсор не знает путей
  приложения. Защита — режим наблюдения: новое правило сначала `observe`,
  и события показывают, трогают ли путь обычные пользователи. Ловушка
  на `/` запрещена всегда.
- **T15 — вредоносная политика.** Не может внедрить HTML, сделать
  перенаправление, закэшировать ответ, превысить пределы.
- **T5 — узнаваемость.** Учебные ловушки публичны. Ответ ловушки
  отличается от ответов приложения заголовками — например, нет `Server`.
  Подстройка — шаг 10 и этап 8.
- **Обход ловушки другой записью пути** — закрыт нормализацией. Остаётся
  регистр: `/.ENV` на сервере, не различающем регистр, — тот же файл,
  а ловушка его не поймает. Это осознанный выбор точного совпадения.
- **Автор изменения политики неизвестен** — сенсор записывает событие,
  но не знает, кто послал `SIGHUP`. Журнал аудита с автором — control plane,
  этапы 3 и 5.

## Как это проверено

- **Разбор и проверка.** 32 случая в `TestParseRejects`: повторяющийся
  ключ, регистр, неизвестное поле, данные после документа, корень,
  ненормализованные пути, перенаправление, HTML, JSON-не-JSON, пределы.
  `TestParseReportsAllErrors` — все ошибки перечислены.
  `TestDemoPolicyValid` — учебная политика из репозитория проходит ту же
  проверку, поэтому опечатка в ней упадёт в CI, а не на стенде.
- **Нормализация.** `TestNormalizePath`, `TestMatchEvasions` — шесть
  записей `/.env` совпадают, похожие пути — нет. `FuzzNormalizePath` —
  880 тысяч входов.
- **Касание.** `TestEnforceRespondsAndRecords`, `TestObserveRecordsOnly`,
  `TestSeverityNeverCritical`.
- **Загрузка.** Неверная политика при перезагрузке — прежняя остаётся,
  в копию не попадает. Перезапуск со сломанным файлом — работает копия.
  Нет ничего — без ловушек, но сенсор жив. Испорченная копия
  не применяется.
- **Сенсор целиком.** `TestRunServesTrapsAndReloadsOnHUP`:
  - `/.env` отвечает ловушкой, обычный путь идёт в приложение;
  - настоящий `SIGHUP` применяет новую политику;
  - сломанная политика отвергнута, остаётся прежняя;
  - касание и отказ — в файле событий.
- **Контейнер.** `make smoke`: `/.env` на Juice Shop и `/.git/config`
  на VulnBank отвечают ловушкой, касание записано в файл событий внутри
  контейнера.

Мутационная проверка — 13 поломок, каждую поймал тест:

| Поломка | Какой тест упал |
|---|---|
| принимать неизвестные поля | `TestParseRejects/неизвестное_поле` |
| разрешить ловушку на `/` | `TestParseRejects`, `TestParseReportsAllErrors` |
| принимать ненормализованный путь | `TestParseRejects/не_нормализован` |
| разрешить перенаправление | `TestParseRejects`, `TestParseReportsAllErrors` |
| не снимать `;параметры` при сравнении | `TestNormalizePath`, `TestMatchEvasions` |
| без `path.Clean` при сравнении | `TestNormalizePath`, `TestMatchEvasions` |
| режим наблюдения отвечает ловушкой | `TestObserveRecordsOnly` |
| очень высокая уверенность → critical | `TestSeverityNeverCritical` |
| неверная политика сбрасывает ловушки | `TestLoaderStartupAndReload` |
| копия пишется и для неверной политики | `TestLoaderStartupAndReload`, `TestStartupFallsBackToLastValid` |
| при запуске не брать копию | `TestStartupFallsBackToLastValid` |
| ответ ловушки можно кэшировать | `TestTrap` |
| без обработчика SIGHUP | тестовый процесс погиб от сигнала |

## Вопросы для самопроверки

1. Почему политика разбирается пакетом `encoding/json/v2`, а не привычным
   `encoding/json`? Приведите пример, где старый пакет незаметно подменил бы
   намерение администратора.

   <details><summary>Ответ</summary>

   Старый пакет при повторяющемся ключе берёт последнее значение и сравнивает
   имена полей без учёта регистра. Если в правиле случайно два `"mode"` —
   сначала `observe`, ниже `enforce`, — администратор видит первое и думает,
   что правило только наблюдает, а сенсор применяет второе и отвечает
   ловушкой вместо приложения. Новый пакет отвергает повтор, другой регистр
   и, с `RejectUnknownMembers`, неизвестные поля.

   </details>

2. Сканер запрашивает `/static/..//.env;x=1`. Поймает ли его ловушка
   `/.env`? А какой путь получит приложение, если ловушка в режиме
   наблюдения?

   <details><summary>Ответ</summary>

   Поймает: нормализация снимает `;x=1`, а `path.Clean` разрешает `/../`
   и лишнюю `/` — получается `/.env`. Приложение в режиме наблюдения
   получит исходный путь `/static/..//.env;x=1` без изменений: нормализация
   только для сравнения, сенсор прозрачен.

   </details>

3. Администратор ошибся в политике и отправил `SIGHUP`, а потом сенсор
   перезапустился. С какой политикой он работает и откуда её взял?

   <details><summary>Ответ</summary>

   После `SIGHUP` — с прежней, в памяти: неверная не применяется. После
   перезапуска файл всё ещё неверен, и сенсор берёт копию последней валидной
   из `SENSOR_POLICY_CACHE_FILE`. Её он сохранил сам, когда применял
   прежнюю политику, и при чтении проверил так же строго. Об обоих событиях
   записаны `sensor.policy_rejected` и `sensor.policy_loaded` с источником
   `last_valid`.

   </details>

4. Почему ответ ловушки всегда с `Cache-Control: no-store`? Что потерял бы
   продукт без этого заголовка?

   <details><summary>Ответ</summary>

   Перед сенсором может стоять CDN или кэширующий прокси. Закэшировав
   фейковый `.env`, он отдавал бы его следующим сканерам сам, и эти запросы
   не доходили бы до сенсора. Касания терялись бы — а ради касаний продукт
   и существует.

   </details>

5. Почему в compose смонтирован каталог `deploy/policy`, а не один файл
   `demo.json`?

   <details><summary>Ответ</summary>

   Docker привязывает отдельно смонтированный файл к самому файлу, а не к
   имени. Редакторы и `sed -i` сохраняют через замену файла новым,
   и контейнер продолжал бы видеть старый. Сенсор по `SIGHUP` перечитывал бы
   прежнюю политику, хотя администратор её исправил. Замену файла внутри
   смонтированного каталога контейнер видит.

   </details>
