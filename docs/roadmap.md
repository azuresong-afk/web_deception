# Чек-лист шагов по этапам

Живой документ: обновляется в каждом PR. Служит двум целям — видеть, где мы
находимся, и не терять обязательства, отложенные «на потом».

Обозначения: `[x]` сделано и слито в `main`, `[~]` в работе, `[ ]` впереди.

Детальные шаги расписываются при старте этапа. Для будущих этапов указаны
крупные блоки — они уточнятся, когда дойдём.

---

## Этап 0. Модель угроз, ADR, структура репозитория — **завершён**

- [x] Модель угроз по STRIDE: 13 угроз, 3 принятых риска
- [x] ADR-0001…0009: язык сенсора, control plane, pull-конфигурация, очередь,
      хранилище, canary-токены, минимизация данных, монорепо, модель разработки

## Этап 1. Скелет репозитория, docker compose, CI-пайплайн — **в работе**

- [x] **Шаг 1.** Структура репозитория, служебные файлы, ADR-0010 и ADR-0011,
      модель угроз 1.1 (принятый риск R4)
- [x] **Шаг 2.** Сенсор: минимальный сервис на Go — проверка конфигурации,
      `/healthz` и `/readyz`, таймауты, корректное завершение
- [~] **Шаг 3.** Control plane: минимальный сервис на Python и FastAPI,
      управление зависимостями через `uv` с lock-файлом
- [ ] **Шаг 4.** Контейнеры и docker compose: multi-stage сборки, non-root,
      образы по digest, Postgres и NATS, Juice Shop в отдельном профиле
- [ ] **Шаг 5.** CI, качество: линтеры, типы, тесты, покрытие, сборка,
      фильтры по путям, `golangci-lint` с закреплённой версией
- [ ] **Шаг 6.** CI, безопасность: Semgrep с собственными правилами, CodeQL,
      gitleaks, `govulncheck`, `pip-audit`, Trivy, hadolint, actionlint,
      Dependabot, минимальные права `GITHUB_TOKEN`, пины по SHA
- [ ] **Шаг 7.** Процесс: pre-commit хуки, `CONTRIBUTING.md`, conventional
      commits, защита ветки `main`, обязательные проверки
