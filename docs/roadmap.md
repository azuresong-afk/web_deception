## Этап 2. Сенсор MVP — **в работе**

Цель: сенсор встаёт на пути трафика — передаёт запросы приложению,
выставляет 10 учебных приманок, записывает касания как события и при любой
собственной неисправности не мешает приложению работать. Сенсор этапа 2
только наблюдает и записывает, никого не блокирует.

Учебные приманки публичны (ADR-0011): любой, кто прочитал репозиторий,
их узнает. **До этапа 8 сенсор не предназначен для продакшена.**

Решения этапа (приняты ассистентом по поручению владельца 2026-09-23):

- Control plane переходит на distroless в начале этапа, а не на этапе 10:
  кода в нём пока почти нет, и переход дешевле всего сейчас (риск R5).
- Буфер событий со счётчиком потерь появляется на этом этапе, а не
  на этапе 3: запись в файл тоже может зависнуть, а правило «сенсор никогда
  не ждёт» относится к любому получателю событий.
- Скрытые поля форм переносятся на этап 8: лишнее поле доходит
  до настоящего приложения и может сломать его проверку входных данных,
  а для обнаружения подмены пришлось бы читать тела всех POST-запросов.
  Тот же класс атак — подмену состояния на стороне клиента — ловит
  cookie-приманка.
- Метрики на служебном порту — несколько счётчиков в формате Prometheus,
  записанных вручную, без библиотеки `client_golang` и её зависимостей.
- Приманки — интерпретатор политики из файла, а не код под каждую
  приманку: тот же формат потом будет редактироваться в веб-интерфейсе
  (ADR-0018). Вторая учебная цель — VulnBank (ADR-0019).
- До этапа 6 алерт о переходе в fail-open не доставляется человеку:
  событие с уровнем critical, строка ERROR в логе и метрика будут,
  канала доставки нет. Временный пробел, записан в долг.

Шаги:

- [x] **Шаг 1.** Решения этапа: ADR-0018 (политика как данные, настройка

- [~] **Шаг 2.** Control plane на distroless и Python 3.13 (ADR-0020):

- [ ] **Шаг 3.** Проксирование: адрес приложения только из конфигурации,

      нейтральная ошибка 502; Juice Shop за сенсором в изолированной сети;

- [ ] **Шаг 4.** VulnBank за вторым экземпляром сенсора: свой Dockerfile,
      исходники по SHA коммита, зависимости с хешами, отдельная база
- [ ] **Шаг 5.** IP клиента: модуль доверенных прокси — единственное место,
      где разрешено читать X-Forwarded-For; исключение из правила Semgrep
      только для него
- [ ] **Шаг 6.** События: формат v0, маскирование идентификаторов и токенов
      в пути *(долг из шага 3)*, буфер фиксированного размера со счётчиком
      потерь, файл JSON Lines с ротацией, счётчики на служебном порту
- [ ] **Шаг 7.** Fail-open: защита от паник и перегрузки, гистерезис,
      событие при каждом переходе
- [ ] **Шаг 8.** Политика как данные: формат и схема, строгая проверка,
      последняя валидная версия, режим наблюдения; первые ловушки
- [ ] **Шаг 9.** Ловушки с защитой от межсайтовых срабатываний:
      cookie-приманка, приманки только для JSON-запросов (preflight),
      цепочки «наживка → ловушка», заголовки `Sec-Fetch-*` в событии
- [ ] **Шаг 10.** Наживки в ответах: заголовок, robots.txt, HTML-комментарий,
      скрытая ссылка; безопасная правка HTML; фаззинг
- [ ] **Шаг 11.** Бенчмарк задержки: бюджет **+5 мс к p99**; итоги этапа;
      материалы для внешнего ревью
- [ ] Внешнее ревью опытным Go-разработчиком *(обязательство ADR-0009)*

Учебный набор приманок. Наживка — то, что видит атакующий; ловушка — где
касание фиксируется. Разные наживки ведут к разным ловушкам, поэтому
по событию видно, что именно прочитал атакующий.

| # | Наживка | Ловушка | Уверенность |
|---|---|---|---|
| 1 | — | `/.env`: фейковый файл с неработающими учётными данными | низкая |
| 2 | — | `/.git/config` | низкая |
| 3 | — | `/backup.sql` | низкая |
| 4 | строка `Disallow` в robots.txt | путь из этой строки | средняя |
| 5 | скрытая ссылка в HTML | путь ссылки | средняя |
| 6 | HTML-комментарий «документация API переехала» | фейковый список «внутренних» методов | высокая |
| 7 | заголовок ответа с «отладочной» ссылкой | путь из заголовка | высокая |
| 8 | метод из фейковой документации (#6) | запрос, возможный только с preflight | высокая |
| 9 | cookie `SameSite=Strict` со «служебным» значением | запрос с изменённым значением | высокая |
| 10 | учётные данные из фейкового `/.env` (#1) | попытка входа с ними | очень высокая |
