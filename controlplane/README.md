# Control plane

Python и FastAPI. Корреляция событий в профили атакующих, классификация
«шум / целевая атака», решения о реакции, алерты и API для дашборда.

Не находится в критическом пути трафика клиента: если control plane
недоступен, сенсор продолжает работать на последней валидной конфигурации
([ADR-0003](../docs/adr/0003-config-pull.md)).

Решения: [ADR-0002](../docs/adr/0002-controlplane-python.md) (почему Python),
[ADR-0013](../docs/adr/0013-python-dependencies-uv.md) (почему uv).

## Что уже сделано

Приёма событий, корреляции и API ещё нет — они на этапах 3–5. Сейчас
control plane устроен так же, как сенсор, и по тем же правилам: проверяет
конфигурацию и отказывается стартовать при неверной, отдаёт проверки
живости и готовности, пишет структурированный лог.

Одинаковое поведение двух компонентов — не эстетика. Разные правила означают,
что при разборе инцидента нужно помнить, какой компонент ведёт себя как,
а в этот момент такая память подводит.

## Эндпоинты

| Путь | Ответ | Смысл |
|---|---|---|
| `GET /healthz` | всегда `200 ok` | процесс жив, перезапускать не надо |
| `GET /readyz` | `200 ready` или `503 not ready` | можно ли слать сюда запросы |

Всё остальное — `404 not found`, любой метод кроме `GET` и `HEAD` —
`405 method not allowed`. Ответы об ошибках — простой текст со стандартным
названием кода состояния, а не JSON `{"detail": ...}`: поле `detail`
способно содержать текст из запроса, а форма ответа выдаёт фреймворк.

**Документация API выключена по умолчанию.** FastAPI обычно публикует
`/docs`, `/redoc` и `/openapi.json` — полный список эндпоинтов с параметрами
и структурами данных. Это удобно при разработке и одновременно готовая карта
для атакующего, поэтому включается только явным флагом и с предупреждением
в логе.

## Конфигурация

Только переменные окружения. Неверное значение — отказ стартовать
с кодом возврата **2** (ошибка конфигурации) вместо **1** (ошибка работы).

| Переменная | По умолчанию | Описание |
|---|---|---|
| `CP_HOST` | `127.0.0.1` | адрес, на котором слушать |
| `CP_PORT` | `8000` | порт |
| `CP_LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |
| `CP_ENABLE_DOCS` | `false` | открыть `/docs` и `/openapi.json` |

В отличие от сенсора, адрес и порт задаются отдельно: uvicorn принимает их
по отдельности, и разбирать строку `host:port`, чтобы тут же её разделить, —
лишний шаг, на котором можно ошибиться.

## Логи

JSON, одна строка на сообщение, вывод в stderr.

Журнал доступа uvicorn **выключен намеренно**. Он печатает строку запроса
целиком, вместе со строкой параметров, а в параметрах регулярно встречаются
токены сброса пароля, ключи и коды подтверждения. Правила проекта запрещают
логировать токены в любом виде. Свой журнал доступа с заранее выбранными
полями появится на этапе 3, когда будет что записывать.

## Запуск и проверка

Нужен [uv](https://docs.astral.sh/uv/). Установка одной командой:
`curl -LsSf https://astral.sh/uv/install.sh | sh`

```bash
make deps        # установить зависимости строго по uv.lock
make run-cp      # запустить на 127.0.0.1:8000
make lint        # ruff и mypy
make test        # pytest с порогом покрытия 80 %

curl -i http://127.0.0.1:8000/healthz     # 200 ok
curl -i http://127.0.0.1:8000/readyz      # 200 ready
curl -i http://127.0.0.1:8000/docs        # 404 — карта API закрыта
```

Остановка по `Ctrl+C`: uvicorn сам дожидается завершения активных запросов.

## Структура

```
src/webdeception_cp/
    __main__.py   точка входа: проверка конфигурации, затем запуск сервера
    app.py        приложение FastAPI, эндпоинты, обработка ошибок
    config.py     чтение и проверка переменных окружения
    log.py        формат структурированного лога
    version.py    версия сборки (только для логов, не для HTTP-ответов)
tests/            тесты, по файлу на модуль
pyproject.toml    зависимости и настройки всех инструментов
uv.lock           точные версии и контрольные суммы — коммитится в репозиторий
```
